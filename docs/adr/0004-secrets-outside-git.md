# 0004: Secrets outside Git

## Constraint

Everything is in Git, and Git must never contain a secret, not even encrypted: a repository is cloned, forked and kept for years.

## Decision

Secrets live in Vault. Git contains only references: an `ExternalSecret` names a path in Vault, and External Secrets copies the value into a Kubernetes Secret at runtime.

External Secrets authenticates to Vault with its own Kubernetes service account. No Vault token is stored in the cluster or in Git.

The one value that has to come from outside, the database password, is generated by `scripts/up.sh` when the cluster is created. That script plays the part of the operator who would write the secret into Vault by hand.

## Consequence

- Rotating a secret means changing it in Vault. Nothing is committed.
- Vault becomes a dependency of every workload that needs a secret, and has to be operated accordingly.
- `make test` reads the live password from the cluster and searches the repository for it.

## Demo simplification

Here Vault runs in dev mode: in memory, already unsealed, with a fixed root token, and it is re-seeded each time it starts. That would be unacceptable in production. It is used so that the path a secret takes (Vault, External Secrets, Kubernetes Secret, pod) is the real one, without bringing in Vault's storage, unsealing and high availability, which are a subject of their own.
